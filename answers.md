# Ответы — Практическое занятие №12

## Часть A. Базовый Python

| № | Вопрос | Ответ |
|---|---|---|
| 1 | Что такое переменная? | Переменная — это «коробка с названием», в которой программа хранит какое-то значение (число, текст и т.д.). |
| 2 | Зачем переменной давать имя? | Чтобы потом найти и использовать это значение. По имени понятно, что лежит внутри (например, age — возраст). |
| 3 | Чем текст отличается от числа? | Текст (строка) — это слова и символы в кавычках, например "привет". Число — это значение, с которым можно считать: 5 + 3 = 8. |
| 4 | Что такое логическое значение? | Это значение «да» или «нет» (True / False). Например: есть ли у пользователя доступ — да или нет. |
| 5 | Для чего используется список? | Список хранит несколько значений по порядку в одном месте. Например, список доступных инструментов агента. |
| 6 | Для чего используется словарь? | Словарь хранит пары «ключ → значение». Например: «имя → Иван», «возраст → 20». Удобно для параметров инструмента. |
| 7 | Зачем нужны условия? | Чтобы программа могла выбирать, что делать: «если условие выполнено — делаем одно, иначе — другое». |
| 8 | Зачем нужны циклы? | Чтобы повторять одно и то же действие много раз, не переписывая код. Например, обработать каждый файл из списка. |
| 9 | Что такое функция? | Функция — это готовый блок действий с названием. Её можно вызывать много раз, чтобы не писать один и тот же код заново. |
| 10 | Что может получить функция и что может вернуть? | Функция получает входные данные (параметры), выполняет действие и возвращает результат. Например: получила 2 и 3 — вернула 5. |

## Часть B. Модули и библиотеки

| № | Вопрос | Ответ |
|---|---|---|
| 1 | Что такое модуль? | Модуль — это обычно один Python-файл, в котором лежат готовые функции и переменные. |
| 2 | Что такое библиотека? | Библиотека — это готовый набор возможностей (модулей), который написали другие люди и который можно подключить к своему проекту. |
| 3 | Зачем проекту нужны библиотеки? | Чтобы не писать всё с нуля: подключил готовое — и пользуешься. Это быстрее и надёжнее. |
| 4 | Что означает импортировать библиотеку? | Это значит подключить библиотеку к своей программе командой import, чтобы пользоваться её функциями. |
| 5 | Почему нельзя сказать, что любая библиотека уже является частью Python? | Потому что многие библиотеки — это отдельные программы от других разработчиков. Их нужно отдельно установить (например, через pip). В Python «из коробки» есть только стандартная библиотека. |
| 6 | Что такое зависимость проекта? | Зависимость — это библиотека, без которой проект не будет работать. Проект «зависит» от неё. |
| 7 | Почему важна версия библиотеки? | Потому что в разных версиях библиотека может работать по-разному: функции могут измениться или исчезнуть. |
| 8 | Что может произойти при несовместимых версиях библиотек? | Программа может выдавать ошибки, работать неправильно или вообще не запуститься. |
| 9 | Почему программисту выгодно использовать готовую библиотеку? | Это экономит время, кода получается меньше, а готовые библиотеки уже проверены многими людьми, поэтому в них меньше ошибок. |
| 10 | Приведите два примера задач, которые разумно решать готовой библиотекой. | 1) Работа с таблицами Excel и данными (pandas). 2) Отправка запросов к сайтам и API (requests). |

## Часть C. LLM-агент и инструменты

| № | Вопрос | Ответ |
|---|---|---|
| 1 | Что такое LLM-агент простыми словами? | Это программа на основе нейросети (LLM), которая понимает запрос человека и может сама выбрать, какое действие сделать, чтобы его выполнить. |
| 2 | Что такое Tool? | Tool (инструмент) — это внешняя возможность, которую агент может вызвать для конкретного действия: посчитать, найти файл, обратиться к базе данных. |
| 3 | Зачем агенту нужны инструменты? | LLM хорошо работает с текстом, но не всё умеет сама: может ошибиться в расчётах, не видит файлы и базы данных. Инструменты дают ей эти возможности. |
| 4 | Кто принимает решение о необходимости вызвать Tool? | LLM (модель) — она понимает задачу и решает, нужен ли инструмент и какой. |
| 5 | Кто реально выполняет действие Tool? | Программа / сам инструмент. LLM только предлагает вызов, а реально действие выполняет код. |
| 6 | Зачем Tool нужны входные параметры? | Чтобы инструмент понял, что именно сделать. Например, калькулятору нужно знать, какие числа считать. |
| 7 | Зачем Tool нужен результат выполнения? | Чтобы агент получил ответ от инструмента и на его основе сформировал ответ пользователю. |
| 8 | Зачем описывать ошибки инструмента? | Чтобы агент понимал, что что-то пошло не так, и не выдавал неправильный ответ как правильный. Тогда он может сообщить пользователю или попробовать ещё раз. |
| 9 | Почему Tool должен иметь ограниченные права? | Чтобы агент не мог случайно сделать что-то лишнее или опасное (удалить данные, отправить письмо). Даём только те права, которые реально нужны. |
| 10 | Назовите пять возможных Tool для агента. | 1) Калькулятор. 2) Поиск по файлам. 3) База данных. 4) Конвертер единиц. 5) Планировщик (календарь). |

## Часть D. Мини-кейсы

| Ситуация | Tool | Назначение | Вход | Выход | Если ошибка |
|---|---|---|---|---|---|
| 1. «Посчитай 17% от 125 000» | Калькулятор | Точно посчитать процент | Число 125 000 и процент 17 | Результат: 21 250 | Сообщить, что расчёт не удался, и проверить введённые числа |
| 2. «Найди в документе раздел про требования к системе» | Поиск по файлам | Найти нужный раздел в документе | Название документа и что искать: «требования к системе» | Текст найденного раздела | Сообщить, что документ или раздел не найден |
| 3. «Покажи статус обращения №5412» | Внутренний API / база данных обращений | Узнать статус обращения | Номер обращения: 5412 | Статус обращения (например, «в работе») | Сообщить, что обращение не найдено или система недоступна |
| 4. «Обработай пять загруженных документов» | Обработка файлов | Прочитать и обработать документы | Список из 5 загруженных файлов | Результат обработки по каждому файлу | Указать, какой файл не удалось обработать, остальные обработать |
| 5. «Проверь, есть ли свободное время для встречи» | Планировщик (календарь) | Проверить свободное время | Дата, время и длительность встречи, участники | Есть свободное время или нет, варианты слотов | Сообщить, что календарь недоступен, предложить проверить позже |

## Часть E. Найдите ошибку в проектировании

| Ситуация | Что здесь не так? | Как исправить? |
|---|---|---|
| Агент имеет полный доступ ко всей базе данных, хотя ему нужны только статусы обращений. | Агенту дано слишком много прав. Это опасно: он может случайно изменить или увидеть лишние данные. | Дать доступ только на чтение статусов обращений. |
| Агент вызывает калькулятор для каждого вопроса, даже когда расчёт не требуется. | Инструмент вызывается без необходимости — это лишняя работа и время. | Вызывать калькулятор только тогда, когда в вопросе действительно нужен расчёт. |
| Инструмент не сообщает об ошибке, поэтому агент считает операцию успешной. | Агент не знает об ошибке и может выдать пользователю неправильный ответ. | Инструмент должен возвращать понятное сообщение об ошибке, а агент — его проверять. |
| Один Tool одновременно читает файлы, удаляет данные, отправляет сообщения и меняет настройки. | Один инструмент делает слишком много и имеет слишком много прав. Это опасно и запутанно. | Разделить на несколько маленьких инструментов, у каждого — одна задача и свои ограничения. |
| Агент хранит результат, но нигде не фиксирует, какой версией модели он получен. | Потом нельзя понять, откуда взялся результат, и повторить или проверить его. | Сохранять вместе с результатом версию модели (и дату). |

## Часть F. Логика агента без кода

Ситуация: «Сотрудник спрашивает статус обращения №5412».

| Шаг | Что делает система? |
|---|---|
| 1. Запрос пользователя | Сотрудник пишет: «Покажи статус обращения №5412». |
| 2. Что понимает LLM | LLM понимает, что нужно узнать статус конкретного обращения и что для этого нужен инструмент. |
| 3. Какой Tool выбирается | Выбирается инструмент для получения статуса обращения (внутренний API / база данных). |
| 4. Какие данные передаются Tool | Передаётся номер обращения: 5412. |
| 5. Какой результат возвращается | Инструмент возвращает статус обращения (например, «в работе») или сообщение об ошибке. |
| 6. Что проверяет LLM после результата | LLM проверяет, пришёл ли нормальный ответ или ошибка (например, обращение не найдено). |
| 7. Что получает пользователь | Сотрудник получает понятный ответ: «Обращение №5412 сейчас в статусе „в работе“» или сообщение, что обращение не найдено. |
